# Zensu for Copilot CLI 0.7.1

AI-work capture checks CLI capabilities and confirmed product/goal scope before
implementation. Missing or incompatible prerequisites produce actionable setup
instructions without blocking coding or sending a work report. Feature and
optional revision selection, product maintenance and cross-product intent still
require explicit human confirmation.

Pending legacy receipts can be archived and restored through the CLI recovery
commands. Recovery preserves original bytes and pending identities; restored
captures remain paused until explicitly resumed. A persistent local pause also
prevents later Stop hooks from submitting an old goal. No receipt is silently
deleted, reassigned or retried.

Use Zensu CLI 0.20.0 or newer for the recovery commands. The packaged
[CLI installation and update guide](../cli-install-update.md) documents first
installation, `zensu update`, and the fallback for older CLI versions. Existing
feature-scope API requirements remain unchanged.

Validation covers capture transitions, CLI compatibility, receipt preservation,
native packaging, marketplace publication and workflow integration. Deterministic
fixtures are not evidence of a new provider-backed Copilot conversation.

## Update

After marketplace publication completes:

```bash
copilot plugin marketplace update zensu
copilot plugin update zensu@zensu
```

Publication preserves installed plugins and active sessions. Start a fresh
session when you choose to use the updated plugin.
