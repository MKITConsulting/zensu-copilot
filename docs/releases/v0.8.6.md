# Zensu for Copilot CLI 0.8.6

A Copilot stop that runs out of time no longer loops. Under heavy machine load,
an `agentStop` could exceed the dispatcher's 35-second stop budget, and the
dispatcher then blocked the stop with `Internal hook deadline exceeded; workflow
remains pending`. Copilot injected that block as a new prompt, so the agent
started another turn and stopped into the same deadline again. `agentStop` now
has an 80-second dispatcher budget inside a 90-second native registration. The
dispatcher gives every stop check a deadline that ends at least 20 seconds
before it would stop that check, so the shared stop checker applies its own rule
first: a decision already written stands, and a stop without one is released
with a notice that no completion was proven. The same rule applies when the
dispatcher's stop budget runs out or a stop check is killed at its timeout, and
the checker's release notice is no longer dropped. A stop check that fails still
blocks. The pending workflow state survives a released stop, and the next
`agentStop` evaluates it again. `subagentStop` keeps its 35-second fail-closed
budget.

`/zensu-implement` and `/zensu-docs` take the documentation type the release
gate requires from the feature's `feature_scope`: unset needs `user_facing`,
`api` needs `api_reference`, `internal_only` needs `adr`, and `public_facing`
needs `user_facing` plus `tutorial` for L or XL effort. `/zensu-implement` no
longer asks for a new feature revision while one is still open; it reports the
open revision that holds the work.

Deterministic tests cover both changes. The live Copilot CLI 1.0.109 run that
showed the stop loop predates the fix. After the release, a native capture of
the released 0.8.6 and 0.8.5 bytes was made with a scripted model and stop
checks slowed past 35 s (`validation/copilot-stop-deadline-2026-11-21/`). In
that capture, 0.8.6 released the stop with that notice and Copilot made no
further model request, while 0.8.5 blocked the same stop and looped.

Apart from these changes, all 0.8.5 behavior is retained. Publication does not
update installed plugins or restart active sessions. Visible progress remains
assistant-rendered.
