# Zensu for Copilot CLI 0.8.4

Multi-file edits no longer run out of hook time. A multi-file `apply_patch`
normalizes into one call per file, and every matching policy runs once per
call. Tool-admission and completion-policy budgets now scale with the number of
normalized operations: 50 seconds per operation for `preToolUse` and 35 seconds
for `postToolUse`, capped at 250 seconds. Single-operation events keep their
budgets. Copilot's `preToolUse` and `postToolUse` `timeoutSec` rise to 260 so
the fail-closed internal deadline still expires before Copilot's fail-open host
timeout. Policy handlers that outlive their timeout are killed with SIGKILL,
and a multi-operation deadline deny names the operation count.

The edit and create TDD gate runs in one native process on macOS and Linux
instead of starting 9 to 15 short-lived node processes per call. On a local
fixture the median per invocation fell from 913-1710 ms to 130-145 ms, and a
five-file `apply_patch` dispatch from 7596-10258 ms to 3159-3332 ms. Git Bash on
Windows, unrecognized platforms and `ZENSU_TDD_GATE=off` keep the unchanged
shell gate, and a parity suite compares both implementations.

Planning treats a dependency that the specification names as a precondition,
never as consent to install it. A missing one goes through the same install
rule as every other precondition.

Isolated live Copilot CLI captures record the timeout ordering these budgets
rely on: with `timeoutSec` 260 a hook that denies after 250 seconds is awaited
and its deny applied (Copilot CLI 1.0.107), and a hook that outlives its
`timeoutSec` receives SIGTERM while the tool call proceeds (Copilot CLI
1.0.109). See the
[capture record](https://github.com/MKITConsulting/zensu-copilot/blob/v0.8.4/validation/copilot-hook-timeout-2026-11-12/README.md)
for its boundaries.

Apart from these deadlines, all 0.8.3 behavior is retained. Publication does
not update installed plugins or restart active sessions. Visible progress
remains assistant-rendered.
