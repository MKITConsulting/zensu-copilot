# Zensu for Copilot CLI 0.8.2

The TDD skill's precondition discovery (Phase 1.5) no longer stops a run to ask
about routine setup. A precondition is now an item that phase's first step lists.
The host's own progress and question tools are never preconditions, and restoring
the repository's declared dependencies from its committed lockfile (`npm ci`,
`pnpm install --frozen-lockfile`, `yarn install --immutable`, `uv sync --locked`,
`cargo fetch --locked`) runs as routine setup under the host's sandbox and approval
policy. A command that changes the lockfile, adds a dependency or installs a tool
still asks first.

Tools the repository declares are verified through its package manager after the
restore, the audit skips the build only when the lockfile cannot be restored, and
the Autopilot probe restores dependencies before it starts services. In delegated
mode, the rule that blocks instead of asking applies only to tools and
preconditions the specification names.

Validation covers the native build, package integrity and the full deterministic
CI suite. Fixture tests do not claim live Copilot rendering. Publication does not
update installed plugins or restart active sessions.
