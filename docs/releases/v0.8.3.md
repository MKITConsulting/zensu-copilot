# Zensu for Copilot CLI 0.8.3

Startup and prompt enrichment now have enough time for sequential native hooks:
an 80-second dispatcher budget inside a 90-second Copilot allowance. A late
enrichment deadline preserves previously loaded session and Zen context and
reports unfinished hooks. Tool-admission and completion-policy deadlines remain
unchanged.

Context discovery shares one 20-second CLI budget inside its 30-second hook
allowance. Autopilot resume parses principal metadata once and avoids redundant
state-worker startup for an authenticated, safely empty inventory on macOS and
Linux. Existing, corrupt, linked and ambiguous storage retains native validation.

Regression tests cover deadline handling, authority and storage boundaries,
native CLI error envelopes and exact prompt/capture persistence. The reviewed
repair passed all 23 real Copilot presentation checks without hook timeouts;
the coverage follow-up reached 94.86% dispatcher line coverage with all 604 tests
passing. Those runs predate integration with the retained 0.8.2 changes; see the
[validation boundaries](https://github.com/MKITConsulting/zensu-copilot/blob/v0.8.3/validation/copilot-hook-timeouts-0.8.3.md)
and the release workflow for final-source verification.

All 0.8.2 behavior is retained. Publication does not update installed plugins or
restart active sessions. Visible progress remains assistant-rendered.
