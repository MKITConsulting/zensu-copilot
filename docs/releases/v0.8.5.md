# Zensu for Copilot CLI 0.8.5

A large multi-file `apply_patch` is no longer denied for its size. Every policy
run used to receive the event's full lists of tool calls and changes, and every
operation in them embedded the whole patch, so each policy input grew with the
patch. A 95,019-byte patch over five files crossed the 1 MiB input limit of the
capability gate and the session binder and was denied with
`reviewer-capability-v1 deny: trusted hook payload is empty or too large`. Each
policy run now receives the event fields and one operation. An added file
carries its path and content. An updated, moved or deleted file carries its
path with the old and new text, and a move destination also carries its source
path. For that patch the largest policy input fell from 1,636,853 to 32,351
bytes.

A patch line that still holds a lone CR, U+2028 or U+2029 after CRLF
normalization is now denied before any policy runs. Copilot CLI's own
`apply_patch` starts a new line at a lone CR, while every Zensu release up to
0.8.4 splits patch lines only at LF. A file header hidden behind a lone CR
therefore reached none of Zensu's per-file policies, although Copilot creates
that file. Installed copies keep this gap until they are updated to 0.8.5.
Copilot keeps U+2028 and U+2029 inside the line, so for those two characters
the new rejection is stricter than the host: a patch that writes either of them
into a file is denied.

A tool call with an operation whose policy input exceeds 1 MiB is denied before
any of its policies run. The reason names the operation, its path, its size and
the limit, so the change can be split into smaller edits.

A native capture with Copilot CLI 1.0.109 and a scripted offline model records
the multi-file patch and the host's own line splitting. See the
[capture record](https://github.com/MKITConsulting/zensu-copilot/blob/v0.8.5/validation/copilot-patch-inputs-2026-11-20/README.md)
for its boundaries.

Apart from these changes to patch inspection and policy inputs, all 0.8.4
behavior is retained. Publication does not update installed plugins or restart
active sessions. Visible progress remains assistant-rendered.
