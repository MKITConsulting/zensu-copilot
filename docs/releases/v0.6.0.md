# Zensu for Copilot CLI 0.6.0

Automatic AI-work capture now requires an explicitly confirmed product binding.
A repository, feature lookup or inferred product does not count as confirmation.
Use `zensu ai-work bind --product <uuid> --confirm` to establish the binding.
Cross-product work must be selected explicitly; it is never an automatic fallback.

Existing unassigned reports retain their history and appear separately in Zensu.
Capture does not accept work on behalf of a human.

Requires Zensu CLI 0.16.0 or newer and the confirmed-product-scope backend API
introduced by MKITConsulting/zensu-monorepo#1287 (backend 0.102.0).
Deploy the backend and CLI before updating this plugin. Older clients and
unconfirmed scopes fail visibly instead of silently creating unassigned work.

Validation covers capture scope, native package integrity, marketplace
publication and workflow integration. Automated fixtures do not claim a new
provider-backed Copilot conversation. Publication does not modify installed
plugins or active sessions.
