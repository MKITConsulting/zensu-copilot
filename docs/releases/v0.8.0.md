# Zensu for Copilot CLI 0.8.0

Zen mode now carries the current workflow position in intermediate messages and
final answers, including updates between tool calls:

```text
Zensu: ✓implement ▶review ·self-review
```

Native hooks refresh changed progress, supply the first-prompt presentation
contract and clear stale progress when Zen mode or the chain ends. A final-answer
check can request one presentation-only correction per user turn. It does not
repeat work or override a workflow policy block. The line is rendered by the
assistant; it is not a persistent terminal status bar. Intermediate rendering
still depends on model compliance.

Workflow integration tests now avoid repeated project validation within a single
bound helper invocation. Each new invocation still validates its binding. Test
workers are bounded to reduce contention; production hook deadlines are unchanged.

All 0.7.0 feature-scope and automatic-context behavior is retained. AI-work capture
requires Zensu CLI 0.18.0 or newer and the feature-scope backend API introduced by
MKITConsulting/zensu-monorepo#1311 (backend 0.105.0, migration 000624).

See the [validation report](https://github.com/MKITConsulting/zensu-copilot/blob/v0.8.0/validation/copilot-zen-progress-0.8.0.md) for
separate package, fixture and real Copilot presentation evidence. Publication
does not update existing plugin installations or restart active sessions.
